# SketchOS 开发规范（给参与开发的人和 AI 看）

> 这份文档规定了**各个组件之间的约定**。改动约定（路径、配置格式、协议、日志格式）之前，先改这份文档。

## 1. 总体架构

```
┌──────────────────────────── 用户态（全部是我们自己写的） ────────────────────────────┐
│ 图形应用: skterm 终端 · skfiles 文件 · sknote 记事本 · skpaint 画板 · skmon 监视器 ·    │
│           skclock 时钟 · skmusic 音乐 · skabout 关于/架构图                           │
│        │ libsketch（绘图 + 手绘图元 + 字体 + 控件 + 客户端协议）                        │
│        ▼ Unix 域套接字 + 共享内存 (memfd)                                              │
│ sketchd  显示服务器 + 窗口管理器 + 桌面/任务栏/开始菜单                                │
│ sksh     命令行 shell          skbox  多合一工具箱 (ls/cat/ps/top/...)                  │
│ sinit    1 号进程：挂载文件系统、启动并看护服务、关机重启                              │
│ musl libc（第三方 C 库，静态链接）                                                     │
├──────────────────────────────── 系统调用 ─────────────────────────────────────────────┤
│ Linux 6.12 内核（未修改，只是自己裁剪配置 kernel/sketchos.config）                      │
│   bochs-drm 显卡 · i8042 键盘鼠标 · evdev · 8250 串口 · tmpfs/proc/sysfs/devtmpfs     │
│   ALSA + SB16 声卡驱动（OSS 兼容接口 /dev/dsp）                                        │
├──────────────────────────────────────────────────────────────────────────────────────┤
│ 虚拟硬件：QEMU（Windows/WSL）或 v86（浏览器里的 x86 模拟器，WebAssembly）              │
│           两边都插一块 Sound Blaster 16 声卡（端口 0x220、IRQ 5、DMA 1/5）              │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

启动流程：BIOS(SeaBIOS) → 内核 bzImage → 解压 initramfs 到内存根文件系统 → 运行 `/init`（= `/sbin/sinit`）
→ sinit 挂载 /proc /sys /dev … → 按 `/etc/sketch/services.conf` 启动服务：串口 shell、`sketchd` 图形桌面。

## 2. 目录结构

| 目录 | 内容 |
|---|---|
| `kernel/` | 内核配置片段 `sketchos.config` |
| `scripts/` | 构建脚本（在 WSL 里运行） |
| `tools/` | 构建/测试工具：`qemu_harness.py`、`mock_display.py`、`mkfont.py`、`ppm2png.py` |
| `userspace/common/` | 公共工具库 `skutil.h`（日志、字符串、/proc 解析） |
| `userspace/init/` | sinit |
| `userspace/shell/` | sksh |
| `userspace/skbox/` | skbox，每个 applet 一个 `.c` 文件 |
| `userspace/gui/include/sketch/` | 图形库公共头文件（**接口契约**） |
| `userspace/gui/libsketch/` | 图形库实现 |
| `userspace/gui/sketchd/` | 显示服务器 |
| `userspace/gui/apps/<名字>/` | 图形应用，目录名 = 程序名 |
| `userspace/gui/tests/` | 宿主机离线渲染测试 |
| `tests/` | 自动化测试：`boot/`、`sketchd/`、`web/`（要 QEMU/v86），`skbox/`、`shell/`、`ui/`、`widgets/`、`apps/`（不要） |
| `rootfs/` | 原样放进根文件系统的文件（/etc、/root …） |
| `assets/fonts/` | 生成好的 `.skf` 字体 + 字体许可证 |
| `web/` | 网页版（v86） |
| `windows/` | Windows 下的一键运行脚本 |
| `out/` | 构建产物（bzImage、initramfs.cpio.gz） |

## 3. 构建与测试命令

所有构建都在 **WSL Ubuntu** 里进行（`wsl -d Ubuntu`）。重活目录 `$WORK` 默认是 `~/sketchos-work`（WSL 自己的 ext4 盘，快）。

```bash
bash scripts/toolchain.sh     # 一次性：装依赖、下内核源码、编 musl、生成 sk-cc
bash scripts/kernel.sh        # 编内核 → out/bzImage
bash scripts/fonts.sh         # 生成字体（需要联网下载霞鹜文楷；结果提交在 assets/fonts/）
bash scripts/userspace.sh     # 编用户态 → $WORK/build/userspace/bin
bash scripts/initramfs.sh     # 打包 → out/initramfs.cpio.gz
bash scripts/build.sh         # 以上全部 + 网页资源
```

- 编译器是 `$WORK/toolchain/bin/sk-cc`（gcc -m32 + musl + 内核头文件，静态链接）。
- **WSL 可以直接运行这些 32 位静态程序**，所以 shell、工具箱可以直接在 WSL 里单元测试。
- 并行开发时，**每个人用自己的输出目录**，互不干扰：
  `USERSPACE_BUILD=$WORK/build/us-我的名字 bash scripts/userspace.sh sksh`
  `USERSPACE_BUILD=... bash scripts/initramfs.sh --stage $WORK/stage-我的名字 --out $WORK/test-我的名字.cpio.gz`
- 在 QEMU 里自动测试：`python3 tools/qemu_harness.py --initrd xxx.cpio.gz --script test.txt`，
  或在 Python 里 `from qemu_harness import VM`（见文件开头的说明：等待串口输出、串口执行命令、截图、鼠标、键盘）。
  截图是 PNG，可以直接打开看。虚拟机里插着 SB16 声卡，`VM(audio_wav="x.wav")` 把放出的声音录成 WAV 文件。
- 在 v86 里测试（和网页版是同一个模拟器，Windows 上的 node 运行）：`node tools/v86_harness.mjs --script test.txt`，
  脚本格式同 qemu_harness；`--audio-wav x.wav` 录下声卡的声音。v86 的 SB16 要有人“要数据”才会往下播，
  浏览器里是 Web Audio，Node 里由 harness 按真实速度代劳，所以 harness 里声卡也是正常工作的。
- 图形应用的自动测试：`bash tests/apps/run.sh [应用名...]`。不需要 QEMU——`tools/mock_display.py`
  扮演显示服务器，宿主机直接运行 32 位应用，注入鼠标键盘、检查 damage、截图（`$WORK/app-test-shots/`）。
  每个应用一个 `tests/apps/test_<应用>.py`，公共部分在 `tests/apps/apptest.py`。
  应用的调试输出用环境变量打开（`SKTERM_DEBUG=1`、`SKNOTE_DEBUG=1`……，格式写在各自 `main.c` 开头）。
  宿主机上没有声卡：`skmusic` 的测试用 `SKMUSIC_DSP=<普通文件>` 让它把 PCM 采样写进文件，再检查声音的频率。
- 其它不需要 QEMU 的测试：`tests/skbox/run_tests.sh`、`tests/shell/run_tests.py`、
  `tests/shell/test_interactive.py`、`tests/ui/run.sh`、`tests/widgets/run.sh`。
- 网络受限（比如云端环境只允许访问软件源）时，`toolchain.sh` 下载不到内核源码，会改用发行版的
  内核头文件、从 Ubuntu 软件源取 musl 源码：用户态和上面这些测试照常能编译、运行，
  但编译内核、打包 initramfs、QEMU/v86 测试需要能访问 cdn.kernel.org。
- 宿主机离线渲染：`make -C userspace BUILD=... host-tests` 会用本机 gcc 编译 `gui/tests/*.c`，
  这些测试程序把画面写成 PPM，用 `python3 tools/ppm2png.py a.ppm a.png` 转成 PNG 查看。
  离线测试时用 `SKETCH_FONT_DIR=<仓库>/assets/fonts` 指定字体目录。
- 从 Windows 的 Git Bash 调用 WSL 时，要加 `MSYS_NO_PATHCONV=1`，否则 `/mnt/...` 路径会被改写；
  复杂命令请写成脚本文件再 `wsl -d Ubuntu -- bash 脚本.sh` 运行，避免引号转义问题。

## 4. 系统约定

### 4.1 内核命令行
默认：`console=tty1 console=ttyS0 tsc=reliable mitigations=off random.trust_cpu=on loglevel=4`
（最后一个 `console=` 是 `/dev/console`，也就是串口 ttyS0。）

内核里还编进了一段命令行（`CONFIG_CMDLINE`，放在引导程序传来的参数前面）：
`snd_sb16.isapnp=0 snd_sb16.port=0x220 snd_sb16.irq=5 snd_sb16.dma8=1 snd_sb16.dma16=5`——
让 SB16 驱动不走即插即用、直接按固定设置找声卡。这样网页版、QEMU、测试工具的启动参数都不用改。

我们自己的参数（用 `sk_cmdline_get()` 读取）：

| 参数 | 含义 |
|---|---|
| `sketch.mode=1024x768` | sketchd 优先选择的分辨率（默认 1024x768） |
| `sketch.nogui` | 不启动图形界面，tty1 上直接运行 shell |
| `sketch.tz=CST-8` | 时区（POSIX TZ 格式，默认 `CST-8` 北京时间），sinit 设置为所有进程的 `TZ` |
| `sketch.autostart=terminal,clock` | sketchd 启动后自动打开的应用（apps.conf 里的 id，测试用） |

### 4.2 文件路径
| 路径 | 用途 |
|---|---|
| `/sbin/sinit`，`/init` → `/sbin/sinit` | 1 号进程 |
| `/etc/sketch/services.conf` | sinit 的服务表 |
| `/etc/sketch/apps.conf` | 桌面/开始菜单上的应用列表 |
| `/run/sketch/display.sock` | 显示服务器套接字 |
| `/run/sinit/status` | sinit 写出的服务状态（`svc` 命令读取） |
| `/var/log/<服务名>.log` | 服务的 stdout/stderr（配置了 `log=` 时） |
| `/usr/share/fonts/*.skf` | 字体 |
| `/dev/dsp` | 声卡（OSS 接口）：设好格式后 `write()` PCM 采样就能放出声音；`/proc/asound/cards` 列出声卡 |
| `/root/音乐/` | 音乐文件夹：`skmusic` 启动时把这里的 `.wav` 加进播放列表，“导出 WAV”也存到这里 |
| `/usr/share/doc/sketchos/` | 文档（docs/*.md 复制进来） |
| `/root` | 家目录（HOME），只有 root 一个用户 |
| `/etc/profile`、`/root/.skshrc` | sksh 登录 shell 启动时执行 |

### 4.3 `services.conf` 格式（sinit）
```
# 名称     策略      终端          [选项...]                      命令及参数
serial     respawn   /dev/ttyS0                                   /bin/sksh -l
desktop    respawn   /dev/tty1     cond=gui log=/var/log/sketchd.log  /bin/sketchd
console    respawn   /dev/tty1     cond=nogui                     /bin/sksh -l
```
- 策略：`respawn`（退出后自动重启，10 秒内崩溃 5 次则放弃）、`once`（启动一次）、`wait`（启动并等它结束再继续）。
- 终端：作为该服务的 stdin/stdout/stderr 和控制终端；`-` 表示没有终端（/dev/null）。
- 选项（在命令前、形如 `key=value`）：`log=文件`（stdout/stderr 写到文件）、`cond=gui|nogui`、`delay=毫秒`。
- 命令行按空白切分，支持引号。

### 4.4 `apps.conf` 格式（sketchd）
```
# id        图标        名称          主题色     命令（%f 会被替换成参数，没有参数时整个去掉）
terminal    terminal    终端          #4A7BD0    /bin/skterm %f
files       folder      文件          #F29E4C    /bin/skfiles %f
notepad     notepad     记事本        #5BAA62    /bin/sknote %f
paint       paint       画板          #E0605A    /bin/skpaint %f
music       music       音乐          #F28DB2    /bin/skmusic %f
monitor     monitor     系统监视器    #9B7BD4    /bin/skmon
clock       clock       时钟          #3FB0A8    /bin/skclock
about       about       关于本机      #F2C94C    /bin/skabout
```
图标名见 `theme.h` 的 `sk_icon_from_name()`。

`%f` 的规则：sketchd 先把命令按空白切分成 argv，再把**等于 `%f` 的那一个元素**替换成参数字符串——
参数始终是**一个独立的 argv 元素**（不按空格拆分，路径里有空格也没问题）；没有参数时这个元素被删掉。
各应用对这一个参数的理解：文件类应用当作文件/目录路径；`skterm` 如果参数是目录就在该目录打开 shell，
否则把它当作一条命令行交给 `sksh -c` 执行（文件管理器“运行程序”就是这样实现的）。

### 4.5 环境变量
sinit 给所有服务：`PATH=/bin:/sbin`、`HOME=/root`、`USER=root`、`SHELL=/bin/sksh`、`TERM=linux`（串口/控制台）、
`TZ`、`LANG=C.UTF-8`。sketchd 启动应用时再加 `SKETCH_SOCKET`；skterm 给子进程设 `TERM=xterm-256color`。

### 4.6 日志里程碑（自动化测试依赖这些字符串，**不要随便改**）
用 `sk_log_console()` 输出到串口：

| 程序 | 消息 |
|---|---|
| sinit | `sinit: SketchOS <版本> starting` … `sinit: services started` |
| sinit | `sinit: service <名称> exited (status N), respawning` |
| sketchd | `sketchd: ready <宽>x<高> backend=<kms|fbdev> mouse=<vmmouse|evdev-abs|evdev-rel|none>` |
| sketchd | `sketchd: window <id> created app=<应用名> title=<标题>` / `sketchd: window <id> destroyed` |
| sketchd | `sketchd: launch <id> pid=<pid>` |

串口 shell 提示符以 `# ` 结尾（例如 `root@sketchos:~# `）。

## 5. 编码规范

- C 语言（gnu11），4 空格缩进，UTF-8 源文件，**LF 换行**。
- 这是一个“学习操作系统”的项目：**注释用中文**，在关键的地方解释操作系统概念
  （为什么要 fork/exec、为什么 1 号进程要回收僵尸进程、什么是控制终端、mmap 是什么……）。注释讲“为什么”，不要逐行翻译代码。
- 只依赖 musl libc 和内核头文件，不引入其它第三方库。
- 系统调用都要检查返回值；出错时给出有用的信息（`perror`/`sk_log`）。
- 公共函数加 `sk_` 前缀（库）；程序内部函数用 `static`。
- 不要修改别人负责的目录；需要改公共头文件（`gui/include/sketch/*.h`、`common/skutil.h`）时只做向后兼容的**添加**。

## 6. 视觉规范（手绘风格）

- 所有 UI 元素都用 `rough.h` 的手绘图元和 `theme.h` 的标准外观画出，不出现“完美的直线矩形”。
- 颜色只用 `theme.h` 的调色板。背景是纸（`SK_PAPER`，带细微颗粒），线条是铅笔（`SK_INK`）。
- 彩色部分用排线（hachure）或荧光笔（marker）上色，不要大面积平涂。
- 手绘随机种子要**稳定**：同一个控件每次重绘必须一模一样（用控件 id/名字的哈希做 seed）。
- 界面文字用中文；字体用系统字体（霞鹜文楷），正文 16px、标题 20px。

## 7. 性能规范（网页版跑在 v86 里，CPU 比真机慢 10~50 倍）

- **只重绘变化的部分**：客户端只 damage 改过的矩形；服务器只合成被 damage 的区域。
- 鼠标移动不能触发整窗重绘；悬停效果只重绘那一个控件。
- 没有事件时进程必须睡眠（`poll()` 无限等待或很长的超时），不许忙等。
- 定时器按需启用（时钟每秒一次、监视器每秒一次，窗口最小化时可以降低频率）。
- 大块像素操作用整行 `memcpy`/32 位写入，不要逐像素调用带裁剪检查的函数。
