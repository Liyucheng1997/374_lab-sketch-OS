            欢迎来到 SketchOS（手绘操作系统）—— 一份探险地图
            ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~

SketchOS 是一个“学习操作系统用”的系统。它和 Ubuntu 一样基于 Linux 内核，
但内核之上的整个用户态——从 1 号进程到图形桌面——都是我们自己写的，
而且每一行代码都配了中文注释，讲清楚“为什么要这样做”。


一、系统是一层一层搭起来的
--------------------------

    +------------------------------------------------------------------+
    |  图形应用   终端 记事本 画板 文件 时钟 系统监视器 关于本机        |
    |             （都链接了 libsketch：手绘图元、字体、控件）          |
    |                   |  Unix 域套接字 + 共享内存                     |
    |  sketchd    显示服务器 + 窗口管理器 + 桌面（画面全是“铅笔画”的）  |
    |  sksh       命令行 shell（你现在用的就是它）                      |
    |  skbox      工具箱：ls cat ps top ... 几十个命令共用一个程序      |
    |  sinit      1 号进程：挂载文件系统、启动并看护服务、关机          |
    |  musl libc  C 标准库（唯一用到的第三方代码）                      |
    +---------------------------- 系统调用 ----------------------------+
    |  Linux 6.12 内核：进程调度、内存管理、文件系统、驱动……            |
    +------------------------------------------------------------------+
    |  虚拟硬件：QEMU，或者浏览器里的 v86 模拟器                        |
    +------------------------------------------------------------------+

上面每一层只通过“系统调用”向内核要东西：open/read/write 读写文件，
fork/execve 创建进程、运行程序，mmap 申请内存，ioctl 控制设备……
内核是唯一能直接摸到硬件的程序，其它程序都要“请”它帮忙。


二、开机时发生了什么
--------------------

  1. 模拟器里的 BIOS 把内核 bzImage 和一个压缩包 initramfs 装进内存
  2. 内核初始化硬件，把 initramfs 解压成内存里的根目录 /
  3. 内核运行 /init，也就是我们的 sinit，它的进程号是 1
  4. sinit 挂载 /proc /sys /dev /tmp /run，设置主机名、时区
  5. sinit 读 /etc/sketch/services.conf，启动串口 shell 和图形桌面 sketchd
  6. sketchd 接管显卡和鼠标键盘，画出桌面

  动手看看：
    dmesg | head -40                   内核开机时的“日记”
    dmesg | grep sinit                 sinit 记下的每一步
    cat /proc/cmdline                  内核启动参数
    cat /etc/sketch/services.conf      服务表


三、/proc：内核开的一扇窗
------------------------

/proc 里的文件不在任何磁盘上，你每读一次，内核就现场“写”一份最新的内容：

    cat /proc/cpuinfo        CPU 是什么型号
    cat /proc/meminfo        内存用了多少
    cat /proc/uptime         开机多少秒了
    cat /proc/mounts         挂载了哪些文件系统
    ls /proc                 每个数字目录就是一个进程
    cat /proc/1/status       1 号进程 sinit 的详细状态
    ls -l /proc/self/fd      “我”（当前进程）打开了哪些文件

ps、top、free 这些命令，其实就是把 /proc 里的内容整理成表格。


四、进程：一切都从 1 号进程长出来
--------------------------------

    ps                       列出所有进程，注意 PID 和 PPID（父进程）
    svc                      sinit 正在照看的服务和它们的状态

试试 sinit 的“看护”本领：
    svc                      记下 serial 服务的 pid
    kill <那个 pid>          把串口 shell 杀掉……
    （sinit 会打印 "service serial exited ..., respawning"，马上给你一个新的 shell）

每个进程退出后，都要由父进程用 wait() 收尸，否则会变成“僵尸进程”（ps 里状态是 Z）。
父进程先走了的“孤儿”，会被过继给 1 号进程，由 sinit 负责回收。


五、图形桌面
------------

桌面由 sketchd 绘制。应用程序（终端、画板……）和 sketchd 是不同的进程，
它们通过 Unix 域套接字 /run/sketch/display.sock 说话，
画面像素放在双方共享的一块内存里（memfd + mmap），不用来回复制。

  - 双击桌面图标，或者点任务栏上的“开始”，打开应用
  - 在“系统监视器”里看 CPU、内存和进程
  - “关于本机”里有一张手绘的系统架构图
  - 没有图形界面？开机时在内核命令行加上 sketch.nogui，就只用文字界面


六、关机和重启
--------------

    sinit poweroff           关机（等于 kill -USR2 1）
    sinit reboot             重启（等于 kill -TERM 1，或者按 Ctrl+Alt+Del）

sinit 会先礼貌地请所有进程退出（SIGTERM），等两秒，再强制结束（SIGKILL），
然后才请内核断电。


七、接下来去哪里
----------------

    ls ~/示例                     几个小 shell 脚本，演示管道、重定向、变量、循环
    sh ~/示例/1-hello.sh          运行其中一个
    ls /usr/share/doc/sketchos    开发文档（可以用记事本打开）
    help                          sksh 的内建命令

这里所有的文件都在内存里：随便改、随便删，重启之后一切恢复原样。祝你玩得开心！
