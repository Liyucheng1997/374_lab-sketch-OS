AI 设置 让 SketchOS 里的 AI 助手连上 Claude

    密钥只保存在这个浏览器里（localStorage），只发给上面的 API 地址；SketchOS 虚拟机里的程序永远看不到它。 在 SketchOS 里使用 AI：双击桌面上的「AI助手」、按 Ctrl+Alt+A，或者在终端里输入 ai 你的问题。

    这是什么？

    SketchOS 是一个用来学习操作系统架构的教学系统。它和 Ubuntu 一样建立在 Linux 内核之上——而且就是原版的 Linux 6.12，一行没改； 不同的是，内核之上的一切都是我们自己从零写的：1 号进程 sinit、命令行 sksh、工具箱 skbox、 显示服务器 sketchd，还有终端、文件、记事本、画板这些应用。所有界面都是手绘风格：铅笔线条、蜡笔排线、方格纸。

    AI 是怎么接进操作系统的

    AI 是 SketchOS 的一项系统服务：开机时 sinit 启动 AI 服务 skaid，它在 Unix 域套接字 /run/sketch/ai.sock 上等待“前台”——图形界面的AI 助手和终端里的 ai 命令。 你提一个要求，skaid 就把对话交给 Claude（默认 claude-opus-5-5）；模型想动手时会回一个“工具调用”， skaid 替它运行命令、读写文件、打开应用，再把结果交回去，直到任务完成。

    可是这台虚拟电脑没有网卡。于是我们给它插了第二个串口 /dev/ttyS1，另一头接在这个网页的 JavaScript 上： skaid 把请求写进串口，网页加上你的 API 密钥发给 Claude，再把流式回应一个字节一个字节写回去。 网页只是一块“只会和 Claude 说话的网卡”——对话历史、调用哪个工具，全在虚拟机里决定；而密钥从不进入虚拟机。

    点下「开机」之后发生了什么

    1. 下载：浏览器下载 v86 模拟器（v86.wasm）、两个 BIOS、内核 bzImage 和根文件系统 initramfs。
    2. BIOS 自检：v86 模拟出一台完整的 PC——CPU、内存、显卡、键盘鼠标、串口、时钟芯片。SeaBIOS 先运行，做硬件初始化。
    3. 内核启动：Linux 解压自己，初始化内存管理和进程调度，加载显卡、键盘、串口驱动，再把 initramfs 解压成内存里的根文件系统。
    4. sinit：内核运行的第一个程序 /init（1 号进程）。它挂载 /proc、/sys、/dev，按 /etc/sketch/services.conf 启动各项服务，并负责回收“僵尸进程”。
    5. 桌面：sketchd 通过 DRM 接口拿到显存，画出手绘风格的桌面；应用通过 Unix 域套接字连上它，把画好的窗口放进共享内存交给它合成。

    画面是怎么出现在网页上的？sketchd 把像素写进显存，v86 每一帧把这块显存画到页面的 <canvas> 上。 鼠标则是浏览器把指针位置写进一个“VMware 后门端口”，系统里的驱动在每次鼠标中断时去读它——所以不用锁定鼠标指针，系统里的光标也能和你的鼠标严丝合缝。

    使用小提示

    • 点一下屏幕，键盘输入才会发给 SketchOS；点屏幕外面，或者同时按下再松开 Ctrl+Alt，就把键盘还给网页。
    • Ctrl+Alt+T 打开终端，Ctrl+Alt+A 打开 AI 助手（先在「AI 设置」里填好 API 密钥）。
    • 串口控制台就是这台电脑的第一个串口 ttyS0，上面也跑着 sksh，适合敲命令、看启动日志；在 sinit 出问题、图形界面起不来时尤其有用。
    • 全屏时，Chrome / Edge 会把 Esc、Ctrl+W 这些快捷键也交给 SketchOS；长按 Esc 退出全屏。
    • 截图保存的是虚拟显卡里的原始画面（PNG）。
    • 浏览器里的模拟比真机慢 10～50 倍，开机要等一会儿。系统完全运行在内存里：刷新页面或者重启，所有改动都会消失。
    • 手机 / 平板上：点按 = 鼠标左键，按住拖动 = 拖动，长按 = 右键；「屏幕键盘」按钮可以弹出输入法。
    • 想看看纯文字界面？在网址后面加上 ?append=sketch.nogui。
